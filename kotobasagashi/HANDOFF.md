# kotobasagashi（言葉さがし）— 引き継ぎメモ

## 概要
10×10の文字盤にかくれた言葉をドラッグで見つける言葉さがしゲーム（たて・よこ・ななめ・逆さ読み対応、1分間チャレンジ）。
構成＝`index.html` 1ファイル完結（CSS/JS/辞書込み）。localStorage 未使用（記録は持たない）。
  ★↑は古い。いまは ことば図鑑（`kotobasagashi:zukan:v1`）と じこさいこう（`kotobasagashi:best:v1`）を localStorage に持つ。
- ★**💾 きろくの バックアップ＆ひきつぎ（2026-09-16）**: backup-kit.js（全アプリ共通・同一ファイル）を同梱し、キーが2つなので v2 の collect/restore（どちらも `_mae` に1世代退避）。スタート画面の 図鑑ボタンの下に「💾 きろくを まもる」（kotobasagashi-cache-v10）。
  あわせて全アプリ共通の「保存の見はり」が `<head>` 先頭に埋めこまれた（原本 `../hozon-guard.js`・ルート HANDOFF 参照。手で直さない）。SWは backup-kit.js も先に入れる。

## PWA化（2026-07-07・全アプリ一括）
- `manifest.json` / `sw.js` / `icon.svg` を追加。index.html に theme-color / manifest / apple-touch-icon / SW登録（http(s)のみ）を追記。
- SWキャッシュ名は「kotobasagashi-cache-v1」。ローカルアセット全部をプリキャッシュ（ネットワーク優先・失敗時キャッシュ）。**アセットを更新したら sw.js の CACHE を繰り上げる**こと。
- **注意: Cache Storage は同一オリジン（GitHub Pages）で全アプリ共有**。activate の掃除は自アプリのプレフィックスだけを対象にしてある。`k !== CACHE` だけの条件に戻すと他アプリのオフラインキャッシュを消すので戻さない。

## 「言葉が見つからない・盤面がランダムすぎる」を直した大改修（2026-09-06）

### 何が問題だったか
- `generateGrid()` は `PLACEABLE`（辞書5400語ぜんぶ）を**文字数の昇順にソート**して先頭から40語置いていた。
  つまり **仕込まれる言葉はほぼ全部2文字**、しかも大人でも知らない難語が混ざる。
  3〜6文字の「見つけがいのある言葉」がほとんど入っておらず、
  「たて・よこ・ななめ、どこにも言葉がない」ように見えていた。
- 埋め文字が `CHAR_POOL` の均等ランダム。「ゃ ゅ ょ っ ぱ行 ぢ づ」が同じ確率で出るため、
  日本語に見えない・その1マスがほぼ死にマスになる盤面だった。
- ヒントは10秒でいきなり答えの文字列。段階がなかった。

### 直したこと

**1. テーマ語彙 `THEME_SETS` を新設（322語・10テーマ）**
たべもの / どうぶつ / がっこう / からだ / のりもの / しぜんとてんき / いえとくらし /
あそびとスポーツ / きせつとぎょうじ / うみのいきもの。
すべて小学生が知っている言葉で、読み(r)は CHAR_POOL の文字だけ（**「ー」「ぁぃぅぇぉ」は使えない**ので
「らーめん」「さっかー」などは入れられない。追加するときは必ず確認すること）。

**2. `EXTRA_WORDS4` を新設（65語・うち48語は辞書に無かった）**
「あまい / すっぱい / みんな / じぶん / たしざん / にっちょく / おもしろい」など、
**見つけたのに正解にならなかった**であろう日常語を補充。

**3. 盤面づくりを作り直した（ここが本丸）**
- `PLACE_PLAN = [6,5,5,4,4,4,4,3,3,3,3,3,3,2,2,2,2,2]` … 文字数の設計図。18語を必ず仕込む。
- 選ぶプールを `EASY_BY_LEN`（テーマ語＋EXTRA_WORDS 1〜4＝**子どもが知っている言葉だけ**）に限定。
  辞書5400語は「答えとして受けつける」用にだけ使う（`WORD_SET` は今までどおり全語）。
- `THEME_RATE = 0.62` … 6割はその回のテーマの仲間。残り4割は関係ない言葉。
  **全部テーマにすると当てずっぽうが効きすぎて面白くない**ので、ここは意図的に混ぜている。
- `placeWordSmart()` … 置ける場所を全部出し、**すでにある文字と交差する置き方を8割優先**する。
  交差させると盤面がつながり、1つ見つかると近くの言葉も連想しやすくなる（依頼の「関連する言葉」への答え）。
- **`protectedCellSet()` を必ず渡すこと**。渡さないと後から置く言葉が前の言葉を上書きして壊し、
  「かくれ ことば ○こ」がウソになる。実測で 200盤面×18語すべて無事に置けている。
- `FILL_CHARS` … 埋め文字は頻出ひらがなを重み付けした専用プール。小さい仮名・ぱ行は入れない。
  さらに仕込んだ言葉の文字を35%混ぜて盤面をなじませる。

**4. 仕込み言葉の管理 `hiddenWords`**
- `{word, obj, cells, theme}` の配列。ヘッダーに「かくれ ことば ○こ」として出す。
- `refreshHiddenWords()` … 盤面が書きかわったあと、**本当に残っている言葉だけ**に数え直す。
- `replenishHiddenWords()` … `MIN_HIDDEN = 9` を下回ったら、既存の言葉を壊さない場所に新しく仕込む。
  これで**ゲーム後半も「言葉がある盤面」が続く**。30回連続で見つける自動テストで常に9語を維持。

**5. 段階ヒント（依頼の「5秒でうっすら色」）**
`checkHint` は 400ms ごと。最後に見つけてからの経過で
- **5秒** → 言葉の**先頭1マス**がうっすらオレンジに脈打つ（`.hint-1`）
- **9秒** → 言葉ぜんぶがもっと薄く光る＋「◯文字の言葉」と教える（`.hint-2`）
- **14秒** → 言葉そのものを文字で教える
色は **背景ではなく `box-shadow: inset`** で付けている。背景を変えると黄緑/赤のレベル色が消えてしまうため。
ヒントに選ぶのは `hiddenWords` の中の3文字以上・短い方の半分から（2文字は当てても達成感が小さい）。

**6. 遊びの追加**
- 今回のテーマをヘッダーにチップ表示。テーマの言葉を見つけると **+30pt**。
- **れんぞく（コンボ）**：8秒以内に次を見つけると継続。+10pt×連続数（最大+50）。
- **時間ボーナス**：4文字以上で +3秒、6文字以上で +5秒（上限99秒）。長い言葉を狙う動機になる。
- ボーナスの内訳を盤面の上にふわっと出す（`showBonusBadges`）。
- **じこさいこう記録**を `localStorage['kotobasagashi:best:v1']` に保存（`{score, count}`）。
  記録は**下げない**（`saveBest` は Math.max）。スタート画面とゲームオーバーに表示。
- ゲームオーバーの「新たに知ってほしい言葉」を、**その盤面に実際にかくれていたのに見つからなかった言葉**に変更。
  ランダムな難語より、くやしさが残るぶん覚えやすい。

**7. オフラインのバグ修正**
`sw.js` の ASSETS に `../shiritori/dictionary_output.js` が入っておらず、
**オフラインだと言葉が1つも正解にならない**状態だった。追加して CACHE は v3 → **v4**。

### 触るときの注意
- `buildDictionary()` は2回目以降スキップする（`WORD_SET.size > 0` で早期 return）。
  語彙リストを足したらページを再読み込みすること。
- テーマ語を足すときは、読みに「ー」や小さい母音が入っていないか必ず確認する（盤面に置けなくなる）。
- 同じ読みの言葉は先に並んだ方の意味が残る（`WORD_MAP`）。THEME_SETS が最優先なので、
  同音異義（あめ＝雨/飴、くも＝雲/蜘蛛）は**どちらを見せたいかでテーマ側の並び順を決める**。
  いまは 雨・雲 を残し、飴・蜘蛛 はテーマ語から外してある。

## 語彙を12万語に拡張＋テーマボーナスの明示（2026-09-06 その2）

### きっかけ
「さが（佐賀）・さゆ（白湯）みたいに、ふつうにある言葉が正解にならない」という指摘。
辞書は約5400語しかなく、日常語の取りこぼしが多かった。

### やったこと

**1. `kotoba-dict.js`（約124000語）を追加**
- SudachiDict（Apache-2.0／一部 UniDic BSD）の生CSVから機械生成。**作り方は `build-dict.md` に全部書いてある。**
- 読み＋代表表記だけを持つ（意味は無い）。**意味つきの約5400語は今までどおり `WORD_MAP` が持つ**ので、
  ゲームオーバーの言葉カードは今までどおり意味が出る。大辞書だけの言葉は
  「じしょに のっている言葉。よく見つけたね！」と出す。
- 2.1MB（gzipで約820KB）。前方一致圧縮ずみ。展開は起動時に77ms。
- **不適切語403語を除外済み**（子ども向けアプリなので必須。フィルタは減らさないこと）。
- 出典表記は `kotoba-dict.js` 先頭とスタート画面の `.credit` の両方。**絶対に消さない**（CLAUDE.md §7）。

**2. 判定は2段構え `lookupWord()`**
意味つき辞書 → 大辞書 の順に見る。逆さ読みも同じ。

**3. 2文字問題（重要・設計判断）**
「よく使うひらがな2文字」の組み合わせを20万回サンプリングしたところ、
**約65%が何かの言葉として辞書に載っている**（2文字語は2878語しかないが、2文字空間がほぼ埋まっている）。
つまり2文字を正解にすると「となりの2マスを片っぱしからなぞるだけ」で点が入る。
3文字なら10%、4文字なら0.5%。
→ ユーザーに確認したうえで **2文字も正解のまま（`MIN_ANSWER_LEN = 2`）**とした。
   「ふつうの言葉が不正解になる気持ち悪さ」の方を避ける判断。
   **スパム気味の遊び方が問題になったら `MIN_ANSWER_LEN` を 3 にするだけで切りかえられる**
   （スタート画面の説明文も合わせて直すこと）。
- ただし **盤面に仕込む言葉は3文字以上**にそろえた（`PLACE_PLAN = [7,6,6,5,5,5,4,4,4,4,4,3,3,3,3,3,3,3]`）。
  2文字は偶然いくらでもできるので、わざわざ仕込む意味がないため。

**4. テーマボーナスをはっきり見せた**（依頼）
- ボーナスの吹き出しを種類別の色に。`🎏 テーマボーナス ＋30pt` / `🔥 3れんぞく ボーナス ＋20pt` / `⏱ ながい言葉ボーナス ＋5びょう`
- みつけた言葉バーとゲームオーバーの言葉カードに、テーマの言葉なら**テーマの絵文字と色**をつける
- ゲームオーバーに「🎏 きょうのテーマ「きせつとぎょうじ」の言葉を N こ みつけたよ」を追加
- スタート画面の説明にも「テーマの言葉は テーマボーナス +30pt！」を明記

### ついでに直したバグ
- `registerHidden` の `theme` フラグが `wordObj.t` の有無で判定していたため、
  **別テーマの言葉まで「今回のテーマ」扱い**になっていた。`currentTheme.words` に入っているかで判定するよう修正。
- 見つけてから文字が入れかわるまでの0.7秒に**同じ場所をもう一度なぞると二重に得点できた**。
  `found` クラスが付いているセルを含む選択をはじくようにした。

### キャッシュ
`sw.js` の ASSETS に `./kotoba-dict.js?v=1` を追加、CACHE は v4 → **v5**。

## 見つけた言葉に「意味」をつけた（2026-09-06 その3）

### きっかけ
「じしょに のっている言葉。よく見つけたね！」としか出ない言葉が多く、
**せっかく新しい言葉に出会ったのに意味が分からないのが もったいない**という指摘。

### 容量の答え（実測）
12万語すべてに意味をつけると **約9MB増** で現実的でない。
しかし実際に意味データが用意できるのは38.9%（48277語）で、**2.7MB**（gzip 1.0MB）で収まった。
しかも**短い言葉ほどカバー率が高い**（2文字69%／3文字56%／4文字45%／8文字14%）ので、
子どもが実際に見つける言葉はだいたい説明が出る。日常語55語のプローブでは95%。

### やったこと
- **ファイルを2つに分けた**
  - `kotoba-dict.js`（2.1MB）… 読み＋表記。正解判定に必要なので普通に読み込む
  - `kotoba-imi.js`（2.7MB）… 意味。**`defer` であとから読み込む**ので、ゲーム開始を待たせない。
    読み込めなくても遊べる（意味が出ないだけ）。展開は両方で85ms。
- 表記が読みと同じときはデータ側で省略（「かたつむり」など）。
- 意味の優先順位は **意味つき辞書(5977語・子ども向けの説明) → ウィクショナリー**。
  だから「しんかんせん」は今までどおり「日本を走る、とても速い電車。」と出る。

### ついでに直した品質バグ（地名）
`extract2.py` で地名を全部落としていたため、**「とうきょう」の代表表記が「東境」**になっていた
（東京は固有名詞/地名なので落ちていて、まれな同音語が繰り上がっていた）。
- 地名も候補に戻し、`市町村区郡丁目字` を含む小字を除外
- そのうえで **「ウィクショナリーに意味がある地名だけ残す」**（これで小字5.4万件が落ちる）
- 47都道府県＋主要都市は取りこぼすので `FORCED` で手当て
- 表記選びに**カタカナ加点(+1200)**を追加（「サクラ」より「桜」、「オオサカ」より「大阪」を選ぶため）

### 残っている限界
「ゼド」「ダル」のように、意味データが存在せず説明が出せない言葉が61%ある。
その場合は今までどおり「じしょに のっている言葉。よく見つけたね！」と出る。
**もし「意味が出せない言葉は正解にしない」方針にするなら**、
`kotoba-dict.js` を意味つき48277語だけで作り直せばよい（容量も減る）。
ただし「たこあげ」のように、ふつうの言葉でも意味データが無いものが落ちる点は要注意。

### キャッシュ
`sw.js` に `./kotoba-imi.js?v=1` を追加、`kotoba-dict.js` は `?v=2` に繰り上げ、CACHE は v5 → **v6**。

## 「意味が出せない言葉は正解にしない」に方針変更（2026-09-06 その4）

その3では12万語を正解にして、意味が出せるのはその38.9%だった。
ユーザーの判断で **「意味を説明できる言葉だけを正解にする」** に変更。

### 結果
| | 変更前 | 変更後 |
|---|---|---|
| 正解になる語 | 124028語（意味は38.9%） | **43154語（意味100%）** |
| ファイル | 2つ（2.1MB＋2.7MB） | **1つ（2.9MB／gzip 1.2MB）** |
| 展開時間 | 85ms | **54ms** |
| ランダム2文字が正解 | 65% | **48%** |
| ランダム3文字が正解 | 10% | **5.7%** |
| 日常語70語のカバー | 100% | **96%**（残り3語も子ども向け辞書にあるので実質100%） |

容量も処理も軽くなり、遊びのバランス（当てずっぽうの効きにくさ）まで良くなった。
「ゼド」「ダル」のような、意味も説明できない言葉が正解になることは無くなった。

### 意味の品質チェックを追加
「意味は必ずある」前提にしたので、`useless_gloss()` で使いものにならない説明をはじく：
- 6文字未満
- 見出しを言いかえただけ（「桜 → サクラ。」「魚 → さかな。」）
- 「のこと」「同じ」「未詳」だけ
これで48277語 → 43154語になった（約5100語は説明が使いものにならず除外）。

### コード側のガード
`lookupWord()` で **大辞書の語に意味が無ければ不正解を返す**。
データ側でも意味なしの語は入れていないが、将来データを作りなおしたときの保険。
検証：`BIG_WORDS` 43154語すべてに意味あり／`WORD_SET` 5977語すべてに意味あり（実測0件の欠落）。

### 子ども向け辞書との関係（変わらず）
`WORD_MAP`（約6000語・手書きのやさしい説明）が最優先。
だから「たこあげ」「らんどせる」「ぎょうざ」のように大辞書に無い言葉も正解になるし、
「しんかんせん」は「日本を走る、とても速い電車。」というやさしい説明のまま。

### キャッシュ
`kotoba-imi.js` は**削除**。`kotoba-dict.js` は `?v=3`、CACHE は v6 → **v7**。

## ランク調整・アプリ集ボタンの位置・ことば図鑑（2026-09-06 その5）

### 1. 神ランクが簡単に取れてしまう問題
**原因はスコアではなく「じかんボーナスに上限が無かった」こと。**
4文字以上を見つけるたびに +3〜5秒もらえるので、長い言葉を見つけ続けるかぎり
ゲームが終わらず、スコアがいくらでも伸びていた。

- `TIME_BONUS_LIMIT = 20`（1ゲームでのばせるのは合計20秒まで）を新設。
  上限に達したら「⏱ じかんボーナスは ここまで！」と出す。
- ボーナス自体も +3/+5 → **+2/+4** に。持ち時間の上限も 99 → 90秒。
- **RANKS を大幅に引き上げ**（900pt で神 → **3800pt で神**）。
  | | 旧 | 新 |
  |---|---|---|
  | 見習い | 0〜99 | 0〜249 |
  | 剣士 | 400〜499 | 1150〜1549 |
  | 英雄 | 700〜799 | 2500〜3099 |
  | 神 | 900〜 | **3800〜** |
- 目安：自動テストで「4文字以上を15回連続で完璧に見つける」と1230pt（剣士）。
  人が80秒で25語見つけて約2750pt（英雄）。神は35語くらい必要で、かなり難しい。
  **簡単すぎ／難しすぎがあれば RANKS の数字だけ直せばよい。**

### 2. 「🏠アプリ集」ボタンが「みつけた」バーに重なる問題
消すとゲーム中にアプリ集へ戻れなくなるので、**場所をゆずる**やり方にした。
- `.found-bar` の左に `padding-left:122px` をあけ、`min-height` を 44→56px に
- `#kagasen-home` の `bottom` を 10px → 6px にしてバーの中におさめる
- **図鑑画面では非表示**（自前の「← もどる」があり、カードが隠れるため）
CLAUDE.md §7 の「下に自前のバーがあるアプリは位置をずらす」に沿った対応。

### 3. ことば図鑑（新機能）
テーマ語彙322語を集める図鑑。**見つけた言葉に★がつく。**
- 保存は `localStorage['kotobasagashi:zukan:v1']`（読みの配列）。
  **★は一度ついたら消えない**（CLAUDE.md §6「成長は単調増加」）。
- **未取得は「意味」だけを見せて、言葉と読みはかくす**（＋「◯もじ」で文字数だけヒント）。
  最初は逆（読みを見せて意味をかくす）にしていたが、
  **読みが見えていると ？？？ の意味がなくなる**うえ、
  「意味を先に知っている → これ何だろう？さがしに行こう」という動機が生まれないため入れかえた。
  意味は主役なので、未取得のカードでも文字色をうすくしない。
- テーマごとにセクション分け。全部集めると「★ コンプリート！」
- 見つけた瞬間に「📖 ずかんに あたらしく登録！」のバッジ、
  ゲームオーバーに「ずかんに N 語ふえた！」＋その言葉を表示
- 入口はスタート画面とゲームオーバー画面の「📖 ことば図鑑」ボタン
- **図鑑の対象は THEME_SETS だけ**。大辞書4万語を図鑑にすると集めきれないため。
  テーマ語を足せば図鑑も自動で増える（`zukanTotal()` は THEME_SETS から数える）。

### 調べたけど直さなかったこと
子ども向け辞書に「小さい →『スモール。』」のような弱い説明が221件ある。
大辞書の説明に差しかえようとしたが、**大辞書は読みで引くので同音異義語で誤爆する**
（機械「マシーン。」→「常識では考えられない不思議なこと。」＝奇怪の意味、
　硬貨「コイン。」→「貴人に対する尊称。閣下。」）。
危険なので**差しかえない**。直すなら手で1件ずつ。
