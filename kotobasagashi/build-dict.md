# kotoba-dict.js の作り方（言葉さがし・語彙と意味）

`kotoba-dict.js`（43154語・2.9MB／gzip 1.2MB）＝ 読み＋表記＋意味の1ファイル。

## ★いちばん大事な方針
**意味を説明できない言葉は入れない（＝正解にしない）。**
「じしょに のっている言葉」としか出せないのでは、せっかく新しい言葉に出会ったのに
もったいない、というユーザーの判断（2026-09-06）。
語彙12万語のうち意味が用意できた43154語だけを採用している。
`index.html` の `lookupWord()` にも「意味が無い語は不正解」というガードを入れてあるので、
**データを作りなおすときも必ず全語に意味をつけること。**

機械生成なので **手で編集しないこと。** 作り直すときはこの手順で。
生成スクリプトは使い捨てなので、下の仕様どおりに書き直すこと。

## 1. 元データを落とす
```
open http://sudachi.s3-website-ap-northeast-1.amazonaws.com/sudachidict-raw/
# 最新日付の small_lex.zip と core_lex.zip をダウンロードして解凍
```
- `small_lex.csv` … UniDic 由来の基本語彙
- `core_lex.csv` … 一般語・固有名詞など
- notcore_lex は使わない（マイナーすぎてノイズになる）

## 2. CSVの見方（Sudachi辞書フォーマット）
| 列 | 中身 |
|----|------|
| 3 | コスト（小さいほどよく使われる） |
| 4 | 見出し |
| 5〜8 | 品詞1〜4 |
| 10 | 活用形 |
| 11 | 読み（カタカナ） |
| **12** | **正規化表記**（サクラ→桜／トモダチ→友達。表示にはこれを使う） |

## 3. 抽出のルール（この判断がゲームの質を決める）
- 品詞1が 名詞・動詞・形容詞・形状詞・副詞・連体詞・感動詞・代名詞・接続詞 のものだけ
- 数詞・助動詞語幹 は除く
- **活用形は `*` か `終止形〜` だけ**。これを入れないと「はしら」「はしれ」まで正解になる
- 読みをひらがなに直し、**2〜8文字**・`CHAR_POOL` の文字だけ（「ー」を含む語は盤面に置けないので落ちる）
- 固有名詞は **地名だけ tier2 として拾い、最終的に落とす**
  （`赤平市茂尻` のような地名が10万件あってノイズと容量の元になるため。
   人名も同じ理由で入れない）
- 同じ読みが複数あるときは `(tier, コスト)` が小さいものを採用
- **子ども向けアプリなので不適切語をはじく**（`build_dict.py` の `NG_SUBSTR_SURFACE` / `NG_READING`）。
  実測で403語が除外される。ここは足しても減らさないこと。

## 4. 出力フォーマット
1行 = `共通する先頭文字数(1桁)` + `残りの読み` + TAB + `表記`
読みを五十音順に並べて前方一致で縮めてある（3.2MB → 2.2MB、gzipで約820KB）。
展開はアプリ側の `buildBigDictionary()`。実測77msなので起動時に一括展開してよい。

## 5. ライセンス（絶対に消さない）
- SudachiDict … Apache License 2.0 / © Works Applications Co., Ltd.
- 一部 UniDic … BSD 3-Clause / © 2011-2013 The UniDic Consortium

`kotoba-dict.js` の先頭コメントと、**スタート画面の `.credit`** の両方に表記してある。
どちらも消さないこと（CLAUDE.md §7）。

## 6. 出力フォーマット（最終形）
1行 = `共通する先頭文字数(1桁)` + `残りの読み` + TAB + `表記`（読みと同じときは空）+ TAB + `意味`

## 7. 更新したら
- `index.html` の `<script src="./kotoba-dict.js?v=N">` の N を繰り上げる
- `sw.js` の `ASSETS` の `?v=N` も合わせ、`CACHE` のバージョンも繰り上げる
- スタート画面の「じしょは 約5万語！」の数字も直す

# 意味データ（kotoba-imi.js）の作り方

## 1. 元データ
日本語版ウィクショナリーを wiktextract が解析したもの（kaikki.org 配布）。
```
curl -O "https://kaikki.org/jawiktionary/日本語/kaikki.org-dictionary-日本語.jsonl"
```
約180MB・148279行。1行1エントリのJSON。使うのは `word` / `lang_code` / `senses[].glosses[0]`。

## 2. 意味文の整形（ここを手を抜くと使いものにならない）
- `[[リンク]]` `<タグ>` 先頭の `（文語）` などを落とす
- **1文目だけでは足りないことがある**。「桜 → サクラ。」のように1文目が短すぎる場合は
  次の文まで足す（12文字に届くまで）。最大40文字、超えたら「…」
- **他の語義を参照する文は捨てる**（`語義` `上記` `以下、` `本義` などを含む文）。
  「七夕 → 語義1の起源となった…」のような、単独で読めない説明を防ぐため
- **言いかえだけの説明を避ける**。`〜の漢字表記。` `〜の異体字。` などにマッチしたら
  次の語義へ。表記の項目 → 読みの項目 の順に探し、10文字以上の実のある説明を優先する

## 3. 地名の扱い（重要）
SudachiDict の地名は「姥島新田」「北膳前」のような小字が7万件あり、そのままだとノイズ。
かといって**全部落とすと「とうきょう」の代表表記が「東境」になる**（実際にそうなっていた）。
- surface に `市町村区郡丁目字` を含むもの・6文字以上のものを落とす
- そのうえで **「ウィクショナリーに意味がある地名だけ残す」**。これが一番よく効く品質フィルタ
- それでも落ちる都道府県があるので、47都道府県＋主要都市は `FORCED` として手で足す

## 4. 表記の選び方
`score = コスト + (地名なら+2500) + (カタカナだけの表記なら+1200)` が最小のものを採用。
カタカナ加点が無いと「桜」より「サクラ」、「大阪」より「オオサカ」が選ばれてしまう。

## 5. 不適切語フィルタ
**見出し・表記・意味文のすべて**にかける（意味文だけに不適切な語が出ることがある）。
実測で675語が除外される。**減らさないこと。**

## 6. カバー率（2026-09-06 時点）
全体では38.9%だが、**短い言葉ほど高い**ので実用上はほぼ足りる。
| 文字数 | カバー率 |
|--------|----------|
| 2文字 | 69% |
| 3文字 | 56% |
| 4文字 | 45% |
| 5文字 | 33% |
| 8文字 | 14% |
日常語55語のプローブでは **95%** に意味がついた。
