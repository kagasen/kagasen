【レキシバトル / rekishi-battle 引き継ぎ】

■ 現状：第1段（動く骨格）完了（2026-07-15）。コミットは未実施（ユーザーの指示待ち）。
   一周ループ（ホーム→へんせい→3人出撃バトル→勝利→3問クイズ→カード獲得→ずかん反映）を
   ブラウザで実際に動かして検証済み。★iPad実機での確認と、カード画像の投入はこれから。

■ アプリの正体
- 子ども用（学習・記録系）。対象は小6以下（歴史は6年生の学習内容）。
- 小学校で習う歴史人物42人（卑弥呼〜野口英世）のカードを集めて進化させながら、
  にゃんこ大戦争風の簡略リアルタイムバトルで遊び、人物の業績を覚えるゲーム。
- 42人の人物と業績リストはユーザー提供（2026-07-14の会話に全文あり。data化するときは
  この原文を正とする）。

■ 設計合意（ユーザー確定事項。勝手に変えない）
1. バトル形式＝「おかねをためて出撃させる にゃんこ式」（2026-07-20 ユーザー決定で刷新）
   - 旧「3人固定出撃・技ゲージボタン」は実際に遊んだユーザーから
     「ゲージがたまったら押すだけでおもしろくない。自分の選択で勝った気持ちになれない」と
     フィードバックがあり作り直した。旧形式に戻さない。
   - おかねが毎秒たまる（＋ざこ撃破ボーナス）→ 人物ごとのコストを払って何体でも出撃。
     同じ人物の連続出撃は数秒のクールタイム。デッキは最大5人。
   - みかたの城（🏯）がこわされたら負け。**敵の城・町（stage.ebase）をこわしたら勝ち**
     （2026-07-20後半のユーザー要望。ボスは守り役で、たおすと🪙+100ボーナス）。
   - ⭐じだいボーナス: ステージの時代に合う人物は1.5倍つよくなる（へんせい画面と出撃ボタンに⭐表示）。
     「同じ時代の人物をセットで覚える」ための意図的な学習仕掛け。
   - 技（業績）はボタンではなく、出撃した人物が一定間隔で自動発動（カットイン付き）。
2. 技＝人物の業績。カードのレア度で技の数が増える
   - ノーマル=技1つ / レア=技2つ / スーパーレア=技3つ。
   - 例: 聖徳太子 N=「十七条の憲法」、R=＋「冠位十二階」、SR=＋「法隆寺建立」級の大技。
   - SRほど演出が派手になる。42人×最大3技の技テーブルは業績リストから起こす（叩き台→先生監修）。
3. 学習の仕込み（3点セット）
   - バトル中、画面上部に「その時代の人物の情報」が流れる（ティッカー）。
     読めていれば勝利後のクイズが簡単に解ける、が核の仕掛け。
   - 勝利後クイズは「3問セット・3択」。流れた情報から出題。
   - ステージ構成＝歴史年表順（弥生→飛鳥→…→明治）。
4. カード入手ルール（★CLAUDE.md §6「ガチャ不採用」の例外。ユーザー明示合意済み）
   - クイズの成績が良い→ N or R がランダムで1枚。成績が悪くても N を確定で1枚（手ぶら無し）。
   - 排出キャラは全42人からいきなりランダム（未到達時代の人物も出る）。
   - 「狙ったカードが出ない悔しさ」は意図的な設計。もう一回やりたくさせるため。勝手に確定式に直さない。
   - 叩き台の対応表: 3問中 0〜1問正解=N確定 / 2問=R確率30% / 3問=R確率60%（数値は実機調整）。
5. 進化＝自動レベル制（2026-07-20 ユーザー決定。旧「枚数合成」案を置きかえ）
   - 同じ人物のカードは手に入れた瞬間に自動で重なる。N=+1 / R=+5 / SR=+30 レベルぶん。
   - Lv5でレアに進化、Lv30でスーパーレアに進化（LV_RARE / LV_SRARE）。合成のUI操作はない。
   - 強さはレベルで上がる: lvMult = 1 + (Lv-1)×0.05（Lv41で上限3倍・叩き台）。
   - 実装はセーブの cards{id:{n,r,sr}}（累計枚数・減らない）から charLevel() で毎回導出。
     スキーマ変更なし・単調増加で §3 に適合。レベルを直接保存しないこと（二重管理になる）。
6. 敵＝史実の相手役（敵専用キャラ）
   - 例: 大化の改新→蘇我入鹿 / 壇ノ浦→平氏 / 元寇→元軍 / 本能寺→明智光秀 / 幕末→黒船 など。
   - 42人リスト外の人物は敵専用（カード化しない）。対立構造そのものが学習内容。
   - 文化・仏教の時代（聖武天皇・鑑真など戦のない時代）は「疫病」「災い」等を擬人化した敵で立てる（叩き台）。
7. カード絵＝生成AIイラスト・レア度で絵自体が進化（1人3枚×42人=126枚）
   - SVG手描きの似顔絵は不採用（ユーザー判断:「ダサくなる」）。先生が画像生成AIで用意する。
   - 開発はプレースホルダー先行: 命名規約を先に固定し、仮絵（シルエット＋名前）で全実装。
     画像はフォルダに入れるだけで反映される作りにする。
   - 命名規約（叩き台）: images/chars/{id}_{n|r|sr}.webp（例: shotoku_n.webp）。
     42人のid一覧は実装時に確定してこのファイルに表を残すこと。
   - 126枚の合計サイズに注意（1枚100〜200KB目安・WebP推奨）。sw.js の precache 対象と
     図鑑の遅延読み込みを設計する。
8. 表記＝漢字＋全ルビ
   - 人物名・歴史用語は漢字で見せて必ずふりがな（rubyタグ）。テストの字面と一致させるのが狙い。
   - 地の文はやさしい言葉づかい。CLAUDE.md §5「ひらがな中心」のこのアプリでの解釈として合意済み。
9. アプリ名＝「レキシバトル」（フォルダ rekishi-battle）。

■ バグ修正（2026-07-20・Safari実機「自分の城が見切れる」）
- 原因: .unit の CSS margin-left:-32px と JS の left=x-32 が二重がけで、全ユニットが64px左に
  ずれて描画されていた（城で顕在化）。margin-left を削除して解決。**再発注意: .unit に
  margin-left を足さないこと**（CSSにコメントあり）。
- あわせて出撃時に el.style.left を即設定（最初のtickまで左上に一瞬出るちらつき防止）。
- 検証: デスクトップ幅・iPad横(1024×768)の両方で、城=左端+12px・敵拠点=右端-14pxに全体表示。

■ 第1段の実装内容（2026-07-15）
- 構成: index.html（CSS/JS込み・単一ファイル）＋ chars-data.js?v=1（42人・タイプ性能・ステージ3つ。
  データを直したら index.html の ?v= を必ず繰り上げる）。ES2017縛り（?. と ?? 不使用）を
  node release-check.mjs で確認済み（エラー0件。PWA無し/ポータル未登録の警告は第2〜3段の予定分）。
- バトル: 3人出撃リアルタイム戦（rAFループ）。自動前進・自動攻撃、技ゲージ（SKILL_CHARGE=15秒・
  開始時40%）満タンでボタン発動。技効果はタイプ別（せっきん=近くに攻撃×5 / えんきょり=敵全体に×3 /
  かいふく=みかた+150。かいふくは通常時も4秒ごと+18）。すべて叩き台。
  勝利=敵大将のHPゼロ。敗北=3人全滅 or 敵が左端(x≤22)到達。敗北はペナルティなし・再挑戦のみ。
- ティッカー: ステージの ticker 人物の info が上部を流れる（1行11秒・ランダム順ループ）。
- クイズ: ティッカーに流れた info からランダム3問・3択「これはだれのこと？」。誤答時は正解を緑表示
  ＋「おぼえておこう」（責めない）。報酬: 正解0〜1問=N確定 / 2問=R30% / 3問=R60%、人物は全42人から
  ランダム（合意済み仕様。確定式に直さない）。
- レア度: N/R/SR は強さ倍率 RAR_MULT(1.0/1.3/1.6)・デッキには各人物の最高レアが自動で出る。
  進化合成は第2段（獲得枚数は cards{id:{n,r,sr}} に蓄積済みなので後付けできる）。
- セーブ: localStorage "rekishiBattle.save.v1" = {ver, cards, deck, cleared}。loadSave() に
  スキーマ移行ポイント用のガードあり。初回はスターター3枚（卑弥呼・聖徳太子・織田信長=3タイプ揃い）。
- ステージ解放: 順次解放（前のステージクリアで次が開く）＝叩き台。飽きたら常時解放に変える
  （todofuken-bouken の前例あり）。
- 動作確認ハッシュ: #st1 / #st2 / #st3（へんせい飛ばしてバトル直行）・末尾 f で6倍速（例 #st1f）。
- 検証メモ: リモートブラウザ/非表示タブでは rAF が間引かれてバトルがほぼ止まる（実機で前面なら60fps）。
  headless検証時はコンソールで `B.last=0; tick(50);` をループさせると1回0.05秒ずつ進められる。
- 既知の小物: 味方どうしが重なって見える（にゃんこ風なので許容中）／カード演出はCSSアニメ依存。
