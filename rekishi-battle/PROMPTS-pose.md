【レキシバトル バトル用ポーズ絵 / Nano Banana Pro 依頼プロンプト集】

■ 使い方
- 1人につき1回の生成で「4コマ並んだポーズシート」を作る。生成回数は全部で42回。
- 各プロンプトを丸ごとコピペし、その人物の参考画像（既存の顔絵を1人ぶん切り抜いたもの）を添付する。
- 出てきたPNGを rekishi-battle/sheets/{id}_sheet.png という名前で保存し、次を実行するだけ:

      python3 build-sprites.py            （sheets/ にある全部を処理）
      python3 build-sprites.py himiko     （1人だけ）

  images/chars/{id}/stand|walk|atk|down.webp が作られ、ゲームがそのまま拾う（フォルダは自動で作られる）。
  ※ sheets/ は .gitignore 済み（1枚1.5MBあり、GitHub Pages に載せる必要がないため）。

■ 背景について（2026-07-27 に実機で分かったこと）
- 「背景は透明」と頼むと、Nano Banana Pro は **透明そのものではなく、透明を表すグレーの
  市松模様を絵として描いてくる**。alpha は全面 255 で、模様はただのピクセル。
- これは困った話に見えて、実はいちばん都合がよい。濃いグレーと薄いグレーの2種類の背景の上に
  同じ絵が乗っているので、半透明の部分も計算で正確に復元できる（build-sprites.py が自動でやる）。
  だからプロンプトは「透明」のままでよい。単色べた塗りに変えないこと。
- ただし **ふんわりぼかした光（グロー）だけは、どんな方法でもきれいに抜けない**。
  なので全プロンプトに「エフェクトはふちのはっきりした形で描く」を入れてある。
  卑弥呼のシートはこのルールを入れる前に作ったので、光の輪にうっすら模様が残っている。
  気になったら作り直す。他の41人はこのルール入りなので大丈夫なはず。
- ★2026-07-28 追記（12人ぶん処理して分かったこと）。上の「大丈夫なはず」は半分はずれた。
  **色のついた半とうめいの光（金の後光・刀の白い軌跡・オレンジの光）が模様の上にかぶると、
  その中の模様が抜けずに残る**。濃淡の差から色を復元する計算が、色がついたとたんに効かなく
  なるため。残りかすはとなりのコマとつながって、コマの切り分けまで壊す。
  実際 中臣鎌足・聖武天皇・紫式部 の3人はこれで処理できなかった（鑑真・中大兄皇子は
  処理はできたが、こうげきのコマに模様が残っている）。
  ・対策として「まわりとの明暗差が模様どおりか」で拾う方式を試したが、髪や帽子のふちまで
    同じくらい反応してしまい分離できなかった（build-sprites.py にコメントで残した）。
  ・**その手の絵を作り直すときは、背景を「透明」ではなく `#FF00FF` のマゼンタべた塗りで
    頼むこと。** build-sprites.py の単色背景ぬきは色つきの光があっても確実に抜ける。
    プロンプトの「背景は完全な透明（アルファチャンネル）」の行を
    「背景は #FF00FF のマゼンタ一色でぬりつぶす。人物にはマゼンタを使わない」に差しかえる。
- 4コマは「たち／あるき／こうげき（かいふくは いのり）／やられ」。レア度で描き分けない
  （レア度は今もわく色 N=茶 / R=銀 / SR=金 で表現しているので、バトル絵は1セットでよい）。
- 参考画像には文字とまるいわくが焼き込まれているので、各プロンプトに「使わないで」と明記済み。

■ 制限が来たときの優先順位（この順に作れば遊べる範囲から埋まる）
  1. himiko / shotoku / nobunaga（初回スターターの3人。必ず全員が持つ）
  2. imoko / nakanooe / kamatari（st2 飛鳥）
  3. michinaga / murasaki / seishonagon / kiyomori（st3 平安）
  4. あとは時代順に

■ 向きについて（いちばん大事）
- 人物は **かならず画面の右（→）を向く**。左の自分の城から右の敵の城へ進むゲームだから。
- ①たち と ②あるき の2コマを交互に出して歩かせるので、**この2コマの向きがちがうと
  クルクル回って見える**（卑弥呼で実際に起きた。①が右・②が左だった）。
- 全プロンプトに向きの指定を強く書いてあるが、それでも生成AIは左向きを出してくることがある。
  そのときも **作り直さなくてよい**。build-sprites.py が顔（肌色）と髪の位置から向きを判定して
  左向きのコマを自動で反転する。実行したときのログに「向き stand:右 / walk:左→反転 …」と出る。
  ・たおれたコマ(down)は「右向きの人が後ろへふっとぶ＝頭が左」が正しいので反転しない。
  ・自動判定が外れたら手動で: python3 build-sprites.py himiko --flip walk,atk

■ タイプ別のこうげきの考え方
  せっきん(bushi/13人)  = 武器を振り下ろす・前に踏み込む
  えんきょり(chie/24人) = 自分の象徴の持ち物を前に突き出す／かかげる（文化人に武器を持たせない）
  かいふく(inori/5人)   = 手を合わせる・かかげる。光が広がる

■ 生成のコツ
- うまくいかないとき（背景が透明にならない／文字が入る）は、そのチャットで
  「背景を完全に透明にして、文字を消して、もう一度」と追い打ちすると直りやすい。
- 4コマの身長がそろわないときは「4コマとも同じ身長にそろえて、もう一度」。
- 参考画像の人物と顔が変わってしまったときは「参考画像の顔にもどして」。
- 透明背景が出せないモードのときは、代わりに「まっ平らな鮮やかなマゼンタ（#FF00FF）の背景」を
  指定して出させ、あとから色をぬき取る手もある。
